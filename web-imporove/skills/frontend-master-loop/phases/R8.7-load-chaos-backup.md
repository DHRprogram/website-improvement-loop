# R8.7 — Load, Chaos & Backup

## Purpose
Run load tests, chaos drills, and backup restore drill on the redesigned system to ensure it meets production readiness.

## Inputs
- Staging environment with new code
- Load test configurations
- Chaos scenarios

## Outputs
- artifacts/redesign/load-chaos/LOAD_TEST_REPORT.json
- artifacts/redesign/load-chaos/CHAOS_REPORT.json
- artifacts/redesign/load-chaos/BACKUP_DRILL_REPORT.json

## Load Test Steps
1. Define baseline traffic patterns from R1 metrics.
2. Run load test at 1x baseline traffic.
3. Run at 5x baseline traffic.
4. Run at 10x baseline traffic (if stage allows).
5. Measure p50, p95, p99 latency vs baseline.
6. Measure error rate vs baseline.
7. Compare to approved cost delta.

## Chaos Drill Steps
1. Kill one backend pod/process.
2. Introduce network latency (+100ms).
3. Simulate DB connection pool exhaustion.
4. Simulate upstream API timeout.
5. Measure recovery time and SLO impact.

## Backup Drill Steps
1. Take backup of staging DB.
2. Restore backup to another database.
3. Measure time to restore (<10min required).
4. Run data integrity check.

## Steps
1. Run load test at 1x baseline throughput; record metrics.
2. Scale to 5x; verify no crashes; record p95 latency and error rate.
3. Verify cost delta within approved budget using cost-delta.sh guard.
4. Execute chaos drills: pod recovery, network latency injection, DB pool exhaustion.
5. Run backup restore drill against staging database.
6. Verify restore completes within 10 minutes and data integrity holds.
7. Generate LOAD_TEST_REPORT.json, CHAOS_REPORT.json, BACKUP_DRILL_REPORT.json.
8. Validate all three reports pass JSON.parse.
9. Compare results against APPROVALS.json budgets.
10. Update STATE.json with phase completion record.

## Checklist
1. Load test at 1x passes (no regression).
2. Load test at 5x completes without crash.
3. Latency p95 < 2x baseline.
4. Error rate < 1%.
5. Cost delta within approved budget.
6. Chaos drill: pod recovery < 60s.
7. Chaos drill: network latency handled gracefully.
8. Chaos drill: DB pool exhaustion handled gracefully.
9. Backup drill: restore completes.
10. Backup drill: restore < 10 min.
11. Backup drill: data integrity verified.
12. LOAD_TEST_REPORT.json passes JSON.parse.
13. CHAOS_REPORT.json passes JSON.parse.
14. BACKUP_DRILL_REPORT.json passes JSON.parse.
15. All failures documented with rollback action.

## Failure Modes
- Load test causes crash -> stop load test, investigate.
- Recovery > 60s -> HST-09.
- Backup restore > 10min -> HST-08.

## Rollback
- All tests run against staging only; no production impact possible.
- If any drill fails, flip feature flag to exclude new code paths.
- Revert recent deployments if load test shows regression >20%.
- Document all failures in HARD_STOP report and halt for human review.
